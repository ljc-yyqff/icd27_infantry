# 视觉串口职责（当前说明）

视觉侧负责识别、坐标解算、目标运动估计/预测、按手册发送串口指令及记录反馈。IMU反馈可用于视觉姿态补偿；电机执行、到位、保持、限位和保护由电控负责。

串口 115200 8N1，无流控，ASCII，CRLF 结尾，单行正文最多31字符。发送 yr/pr 相对角度（度），速度必填且为1～120度/秒，同时遵守配置的单条指令参数上限。总发送频率不超过50Hz。

不等待上一条到位，不累计机械目标，不因遥测缺失、非有限值、状态或回执缺失锁定后续发送；不会自动切换模式、查询电机状态或撤力。反馈仅供日志和显示。串口写入失败仍会报错，不自动重发相对指令。

e 手动发送 ge；d 手动发送 gd；q 显式撤力并退出。输入结束和串口对象析构不再自动发送 gd。ready 仅表示串口已打开，不代表电机 ACTIVE。电控是否接受指令应查原始反馈日志，串口写成功不等于已执行。

运行：`./build/ascii_tracking/gimbal1_feedback configs/infantry_daheng.yaml`。

视觉跟随：`./build/ascii_tracking/gimbal1_armor_track configs/infantry_daheng.yaml --control=true`。e 开始发送，s 暂停视觉发送，d/q 为手动撤力。识别死区、发送频率及手动跟随时长设置仍是视觉流程参数，不判断电机到位。

日志位于运行目录 logs/gimbal1。旧说明中所有到位等待、运动超时及反馈门槛均已停用，旧配置中的相关参数不再影响发送。

## 2026-10-31 跟踪抖动修正

跟踪入口仍为 `build/ascii_tracking/gimbal1_armor_track`。推荐起始参数：

```bash
cd /home/ros/infantry/ict27_infantry
./build/ascii_tracking/gimbal1_armor_track configs/infantry_daheng.yaml \
  --control=true --control_rate=40 --speed=30 --max_step=1.0 \
  --yaw_gain=2.0 --pitch_gain=1.2 --deadband=10 --deadband_exit=16
```

旧的 `--gain` 是每条指令的系数，现已停用，传入时会明确报错；请移除并改用上述两个以每秒为单位的增益。默认值已经是上面这组。`--min_step` 必须为0，不强制添加最小步长。

每轴独立计算：`修正角速度 = clamp(该轴增益 × 带方向的视觉角度偏差, ±speed)`；`相对增量 = clamp(修正角速度 × 该轴距上次发送的时间, ±max_step)`。单次积分时间最多100ms，防止推理卡顿后补发大步长。丢失目标、过期图像或暂停时清空视觉轴时间，不补算这段时间。总串口频率仍不超过50Hz；双轴交替发送时分别使用自己的时间间隔。`speed` 作为速度上限，同时限制视觉修正速率；实际写入 yr/pr 的速度根据本次增量/积分时间计算，再限制在协议允许的1～speed度/秒。小修正不再固定使用30度/秒，避免将很小角度指令压缩成短促运动；它不保证实际电机速度。

相机单帧队列满时替换旧帧，消费者获取最新缓存图像。默认只对主机取帧后120ms以内的图像生成指令（`--max_frame_age_ms`）。这个年龄从SDK取出帧时计时，不代表曝光到发送的完整延迟，也没有进行图像/IMU硬件时钟同步。

目标按颜色、编号、位置连续关联，同一目标附近按距离优先，避免置信度变化导致切换。首次锁定或位置跳变需要3帧一致；异常跳点本帧不生成指令，持续的新位置可以重新锁定。默认关联距离250原始像素（`--target_jump_px`）；实际快速移动时可结合日志调整。中心默认使用20ms时间常数的轻量滤波（`--center_tau_ms=0`可禁用），重新锁定时不沿用旧中心。滤波会有少量延迟，不做长窗口平均。

每轴进入10像素范围停止修正，偏差重新达到16像素才启动；两阈值之间维持原视觉死区状态。Pitch默认增益低于Yaw，后续按实测分别调整。此处均是视觉指令生成规则，不检查电机到位、执行状态或保护状态，不自动发送gd。

控制模式生成两份同前缀日志：`logs/gimbal1/tracking_*.log`为原始串口收发；`tracking_*.vision.csv`逐帧记录主机帧时间、决策时间、图像年龄、原始/滤波中心、视觉角度、目标是否有效、图像是否可用于控制、发送状态、实际发送轴和增量、该轴积分时间、最近遥测值及其主机接收时间、写入完成时间。时间列使用相同的主机steady_clock秒数；反馈可能比图像早或晚，只供对照，不用于电机控制。原始串口日志已有绝对时间，可通过共同的发送事件关联。CSV每50帧及正常退出时刷盘。

离线验证：`ctest --test-dir build/ascii_tracking -R 'visual_tracking|gimbal1_protocol' --output-on-failure`。覆盖发送频率变化、双轴间隔、死区滞回、停顿后的积分上限、独立Pitch增益、目标跳点/重新锁定、轻滤波、最新帧队列。实体云台的振动与响应速度仍需实际运行确认；这些测试不证明消除了所有过冲。

### 小角度修正的速度匹配

依据2026-10-31反馈检查的跟踪日志，取帧后年龄约9～10ms，近中心存在0.01～0.02度的小增量配固定30度/秒的指令。现在令 `发送速度 = clamp(abs(增量)/积分时间, 1, speed)`，增量算法、方向和协议格式不变。例如0.02度/40ms会使用协议最低速度1度/秒，而不是30；0.2度/50ms使用4度/秒。没有到位等待或电机反馈门槛。协议最低速度1度/秒意味着更小步长仍不能保证整段连续运动；如果实体仍振动，需要结合目标静止/暂停视觉的对照和板端轨迹诊断判断，不能用离线测试声称振动已消除。CSV新增 `command_speed_deg_s` 列记录实际速度参数。

## 手动停止开机服务

服务模式（control/headless/auto_start同时启用）收到SIGTERM/SIGINT时，在关闭串口前发送一次gd。这对应用户的systemctl stop操作，不是保护触发。开机启动仍保持enabled。运行中的错误、目标丢失或缺少遥测不会触发该命令；窗口模式和诊断工具仍使用原来的显式d/q。


## 2026-10-31 单装甲板预测链路

已接入原项目Solver的检查后原始PnP位置解算，以及原 `tools::ExtendedKalmanFilter` 的单装甲板位置/速度估计。没有接入整车多装甲板半径、旋转中心模型，没有调用弹道、开火或旧二进制电控接口。`Solver::solve` 的旧入口行为保留，新 `solve_position` 不套用整车装甲板固定倾角的方向优化。

### 三种运行模式

- `--tracking=pixel`：默认，保留已有像素跟踪输出，不读取预测结果。这保证已有开机服务不会因更新二进制就无提示切换算法。
- `--tracking=shadow`：读取姿态、PnP、状态估计、预测并写入日志；实际发送仍用像素算法。默认不自动使能，窗口按e后才发送。
- `--tracking=predictive`：始终使用与shadow相同的像素基础闭环，只在模型可靠时叠加姿态补偿后的相对提前量和目标角速度前馈。数据不足时本帧只关闭模型叠加，不中断有效目标的基础跟踪；不会据此锁定使能、检查到位或触发gd。

新模式需要 `--control=true` 才能打开串口获得IMU数据；未打开串口时仍可显示图像，但预测会显示 `frame_pose_unavailable`，不会假设云台姿态为零。预测模型不可用只表示没有叠加项，像素基础闭环不会被模型门限阻断。

### 推荐台架顺序

先停止已有服务，避免串口/相机占用：

```bash
sudo systemctl stop ict27_armor_track.service
cd /home/ros/infantry/ict27_infantry
./build/ascii_tracking/gimbal1_armor_track configs/infantry_daheng.yaml \
  --control=true --tracking=shadow --control_rate=50 --speed=60 --max_step=6.0 \
  --yaw_gain=4.0 --pitch_gain=2.5 --deadband=10 --deadband_exit=16
```

先不按e，检查 `reason=ok`、PnP重投影误差、距离是否合理。相机和装甲板静止时，估计速度应接近零。随后固定装甲板、按e让云台对准，检查相机转动期间目标的世界位置是否基本稳定。如果世界位置随云台明显转动，先核对IMU符号、相机外参、物理装甲板尺寸及时间偏移，不应靠加大前馈掩盖问题。

确认补偿正确后，退出再将 `--tracking=shadow` 改为 `--tracking=predictive`，按e比较移动跟踪。将 `--feedforward_gain=0` 可关闭前馈做对照，仍保留PnP与时间预测。

这里读取当前配置的60度/秒上限；若该配置被改小，需要同步命令中的speed。50Hz是全部ASCII行的总上限，不是双轴各50Hz。没有新增相对指令重发。

### 姿态和时间条件

当前9列遥测只有IMU yaw/pitch，没有roll或四元数。因此这是**底座固定、roll近似不变的两轴补偿**，不是完整运动底盘六自由度补偿。旋转按x向前、y向左、z向上构造；原Solver再应用 `R_gimbal2imubody`，相机位置使用已有 `R_camera2gimbal` 和 `t_camera2gimbal`。相机外参必须对应当前实际安装，复制配置文件本身不代表已完成验证。

`gimbal1_tracking` 配置：

- `imu_yaw_sign=1`、`imu_pitch_sign=-1`：把遥测欧拉角映射到上述旋转约定，必须实测核对。
- `imu_latency_ms`：IMU采样到主机收到的估计延迟；`camera_latency_ms`：曝光参考时刻到SDK取帧时间的估计延迟。正数从主机时间中减去。默认均为0，表示尚未测量，不表示真实延迟为零。
- `pose_max_gap_ms=80`：只在相邻接收姿态间隔足够小时插值。Yaw展开处理±180度；未来姿态最多外推 `pose_extrapolate_ms=50`。同一USB突发内不足5ms的接收样本合并为最新值，不从微秒间隔推导角速度。
- `additional_prediction_ms=0`：附加的通信/执行延迟估计。可用 `--prediction_ms=数值` 覆盖。不会自动测出电机执行延迟，也不沿用子弹飞行时间。应依据现场日志校准。
- 预测时刻为主机当前时刻加附加延迟；预测总时长为该时刻减去修正后的图像时刻。超过 `max_prediction_ms=150` 不输出本帧预测。

时间来源仍是主机收到串口、SDK取出图像的steady_clock，不是硬件同步时间。存在串口缓存、相机内部缓存时，仅靠插值不能消除未知时间偏移。原始遥测逐行保留到有界队列，供视觉消费，不只使用每次poll的最后一条。

### 运动估计与相对输出

状态为 `[x,vx,y,vy,z,vz]`，单位米和米/秒。三维位置进入原EKF，观测噪声按相机到世界旋转变换；有重投影误差、位置异常跳变检查。使能ge时重建视觉姿态时间缓存和运动状态，避免混用可能变化的姿态参考基准；换目标、重新锁定或较长图像间断时重新初始化，至少5次有效观测后才使用速度前馈。默认加速度噪声20m/s²，横向位置噪声下限0.001m、径向深度噪声0.06m，后续应按实测调整。

预测位置变换回**当前**相机坐标，得到模型预测角度；减去同一模型在图像时刻的角度，得到相对提前量。控制使用原像素角度加此提前量，不用模型绝对角度替换像素位置，避免PnP角度偏置或位置滤波滞后改变基础闭环。目标世界速度变换到当前相机坐标，计算目标自身造成的视线角速度。默认前馈系数0.8，低于0.5度/秒的估计角速度不参与前馈；只对前馈速度做50ms平滑，不增加像素位置闭环的滤波延迟。

`修正角速度 = 可用的前馈角速度 + 对像素误差与可用提前量的位置修正`；`相对增量 = 修正角速度 × 该轴实际发送间隔`，再按方向、速度和单步角度上限生成yr/pr。**运动目标经过光心时仍可保留前馈**，避免死区把必要跟随速度切断。不会每帧重复发送完整绝对偏差，也不把移动规划设定点当成板端最终目标。

#### 当前固件的遥测带宽限制

现场日志 `tracking_1793429223_32655.log` 中，最长1.722秒没有九列遥测，这段时间有81条命令和81条#GC回执；遥测的tx_dt_ms也记录了约1720ms间隔。不能把上电标称50Hz当作持续可用的姿态流。新的shadow/predictive模式使用配置 `command_rate_cap_hz=25`，有效发送上限是该值与control_rate的较小者，为遥测保留串口调度时隙。像素模式维持原发送频率，不用此上限。

图像/PnP/状态估计仍逐帧更新。两个轴分别按实际时间生成增量，默认最大积分100ms；60度/秒时，6度单步上限覆盖100ms，不会因为每轴命令间隔变长就额外限速。原有单条协议角度上限仍生效。短时姿态外推上限50ms，没有可用姿态时只暂停该帧视觉增量，不保持数百毫秒的伪姿态。

未来若电控能将逐指令回执与姿态遥测独立调度、在连续命令期间也保持稳定的高频姿态，可经验证后提高该配置，最高50Hz。这是串口姿态数据供给问题，不是要求视觉端控制电机执行或到位。本次未修改电控固件。

### 现场预测效果回归修正

`tracking_1793432092_38234` 实测中，有目标帧的PnP重投影误差中位数约6.16像素；固定4像素门限只接受约8%的观测，旧版predictive把这个门限当作整个控制出口，造成发送断续。这是现场效果差于shadow的直接原因。更换为ITERATIVE/SQPNP重算同样角点，中位误差仍约5.9像素，不能仅更换求解器或继续增加增益。

当前predictive采用明确的像素基础加模型叠加结构；几何拒绝、姿态不匹配、估计预热期间，基础像素闭环仍与shadow相同。目标丢失、图像过期仍不生成视觉增量。

PnP门限现在为 `min(max_reprojection_absolute_px, max(max_reprojection_px, max_reprojection_fraction * 最短灯条图像长度))`，默认绝对上限20像素、固定下限4像素、相对门限4%。这适应现场200～300像素高的近距离装甲板，不把20像素一律用于小目标。出图像边界、退化、非有限角点仍不能提供预测叠加。

PnP只提供深度，中心方向与原四角点平均中心的去畸变视线对齐；协方差把较大的深度噪声放在视线径向，避免把距离抖动当成横向移动。横向噪声随重投影误差增加，位置噪声下限从1厘米调整为1毫米。

模型需要连续有效观测才叠加，并在5帧内渐入。默认提前量限制±2度、每轴前馈限制±30度/秒；这两个是视觉模型叠加上限，板端最终速度仍服从speed和协议限制。新增CSV字段 `augmentation_valid`、`yaw_lead_deg`、`pitch_lead_deg`。日志中的model valid表示几何估计可用，overlay表示估计已准备好实际叠加。`--feedforward_gain=0`只关闭速度前馈；严格基础控制对照仍用shadow。
